# Harness configuration service

`createConfigService(): ConfigService` uses pi's configured agent directory. For isolated tests, use `createConfigService({ agentDir: temporaryAbsolutePath })`. No directory is written until a save. Tests never read or write Austin's global agent directory.

Settings edits preserve unknown JSON values, including extension-owned fields. They rewrite whitespace with two-space indentation. Undo restores the exact previous bytes (or removes a newly created file); one last save per path is retained in memory for this server process. Revisions hash UTF-8 file contents; missing files have a distinct revision. Save and undo compare revisions and report outside edits without overwriting. Writes use a sibling temporary file and rename, retaining file permissions. An unrelated process that does not coordinate can still race the final filesystem check/rename; this is not a general filesystem transaction protocol.

Settings responses contain only scoped model/thinking fields, merged model-thinking overrides, paths/revisions and provenance. Unknown settings and credentials are never serialized. Malformed JSON errors omit source text. `model: null` deletes this scope's provider/model defaults; `thinking: null` deletes only default thinking. `modelThinking.level: null` removes only that model's override. Global and project per-model maps merge; the selected model's override takes precedence over default thinking. Pi 0.85.1's fallback thinking is `medium`, and `max` is accepted. These are configured startup values before project trust and model capability clamping; runtime snapshots remain authoritative for applied state.

Editable skills come from project `.pi/skills` and `.agents/skills`, global agent `skills`, home `.agents/skills` (disabled with a test agentDir), and explicitly configured literal local skill paths. They are disk resources, not claims of runtime loading. Package resources, ancestor `.agents` discovery and glob-only configured resources remain inspectable through the runtime, not authorable here. Existing files retain their entire Markdown/frontmatter content when edited. New skills default to project `.pi/skills/<name>/SKILL.md`.

Read/save accept only discovered paths; creation accepts validated skill names in the selected scope. All resource components beneath allowed bases are checked for symlinks, including again at save; linked resource files/directories are not editable. No arbitrary file endpoint or package install is provided.
